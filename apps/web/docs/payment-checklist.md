# 결제 검수표 (2026-11-13 지니 검수, 유샘 요청)

새 유료 상품을 열 때마다 처음부터 다시 검수하지 않도록, 결제가 지나가는 길과 지켜야 할 규칙을 한곳에 적어 둔다.
새 상품은 아래 "새 상품을 열 때 확인할 것" 표만 채우면 된다.

## 1. 결제가 지나가는 길 (모든 상품 공통)

| 단계 | 하는 일 | 코드 |
|---|---|---|
| 1. 구매 버튼 | 엽전이 충분하면 엽전으로 바로 연다. 모자라면 결제창 | `/api/persons/[id]/purchase` → `readingHandlers.handlePurchase` |
| 2. 주문 만들기 | 서버가 가격을 정하고(손님이 보낸 가격은 쓰지 않음) 엽전을 먼저 쓴 뒤 모자란 만큼 주문(pending) | `/api/persons/[id]/checkout` → `payOrders.checkout` |
| 3. 결제창 | 포트원 V2 · KCP. 카카오페이·네이버페이·토스페이는 바로 열림, 카드·계좌이체 | `PayDialog` |
| 4. 승인 확인 | 결제 완료 화면이 서버에 확인 요청 → 서버가 포트원에 다시 조회(상태 PAID · 금액 · 상점 번호 일치) | `/pay/success` → `/api/pay/confirm` → `payOrders.confirmOrder` |
| 5. 열기 | 한 트랜잭션: 주문 paid + 결제 금액 엽전 입금 + 상품 구매(엽전 차감). 구매가 실패하면 돈은 엽전으로 남김(paid_credit) + 관리자 알림 | `confirmOrder` |
| 6. 창을 닫아도 | 포트원 웹훅(Transaction.Paid)이 서버끼리 4~5를 대신 한다 | `/api/pay/webhook` |
| 7. 결제 완료 화면 | "결제가 완료되었어요 · 상품 · 금액" + [지금 풀이 열기](연 시각 기록) | `/pay/success`, `/api/pay/opened` |
| 8. 환불 신청 | 마이페이지 결제 내역 → 요건 확인(열기 전 · 7일 안) → 접수 안내 + 관리자 알림 | `MyOrders` → `/api/pay/refund` → `refund.requestRefund` |
| 9. 환불 처리 | 관리자 화면 [환불 처리] → 포트원 결제 취소 → 기록 '환불됨' + 장부 정리 + 다시 잠금 | `/api/admin/refund` → `refund.adminRefund` |
| 10. 포트원에서 직접 취소 | 웹훅(Transaction.Cancelled)으로 9와 같은 처리 | `refund.refundFromWebhook` |

## 2. 지켜지고 있는 규칙 (코드로 확인)

- 가격은 서버가 고객사 설정(`tenants/<id>.ts` prices)에서만 읽는다. 결제 금액이 주문과 다르면 승인하지 않는다.
- 포트원 결제 ID = 주문 번호. 다른 주문의 결제로 바꿔치기 못 한다. 상점 번호도 확인한다.
- 같은 승인이 두 번 와도(화면 + 웹훅) 한 번만 연다.
- 판매 잠금(`saleOnly`)은 서버에서 막는다: 카드 주문 · 엽전 구매 · 재미관 겹쳐 보기 · 부모님 선물 결제 모두.
- 이미 연 상품은 다시 팔지 않는다(ALREADY_OWNED).
- 결제창에 환불 기준(열기 전 7일 안 전액, 연 뒤 제한)과 미성년자 취소 고지가 있다. 수능 상품은 보호자 결제 안내.
- 환불되면 결제로 들어온 돈만 빼고, 엽전으로 함께 낸 몫은 엽전으로 돌려준다. 이 주문이 연 풀이만 다시 잠근다(부모님 선물은 선물 기록도 되돌림).

## 3. 이번 검수에서 고친 것 (2026-11-13)

| 문제 | 고친 내용 |
|---|---|
| 수능 다음 날(11/20) 시즌이 합격운으로 바뀌면, 수능대박운을 산 손님이 자기 풀이를 못 보게 됨 (열람 표시가 시즌 이름별) | 시즌 전환을 껐다(`SEASON_SWITCH=false`, 유샘 결정 "합격운은 서비스하지 말자"). 수능 당일이 지나면 새로 팔지 않는다(`examSaleOpen`) |
| 부모님 선물 결제는 판매 잠금·판매 기간을 확인하지 않았음 | 선물 주문·선물 엽전 구매 모두 확인 |
| 결제 앱에서 다른 창으로 돌아와 로그인이 풀리면 "로그인 후 이용" 오류만 보임 (돈은 빠짐) | 로그인 화면으로 보냈다가 같은 결제 완료 화면으로 돌아와 마저 연다 |
| 결제창 보호자 안내의 버튼 이름이 실제 버튼과 다름 | "[부모님께 선물 부탁하기]"로 맞춤 |
| 환불 기능이 없었음 | 1장의 8~10 새로 만듦 |

## 4. 아직 남은 것 (유샘 확인 필요)

| 항목 | 내용 |
|---|---|
| 포트원 웹훅 | 포트원 관리자 화면에서 결제 완료(Paid)와 결제 취소(Cancelled) 둘 다 보내는지, Vercel에 `PORTONE_WEBHOOK_SECRET`이 있는지. 없으면 창을 닫은 손님 결제가 바로 열리지 않고, 포트원에서 직접 취소한 건이 사이트에 반영되지 않는다 |
| 알림 받는 곳 | 환불 신청·결제 뒤 구매 실패 알림은 `ERROR_ALERT_WEBHOOK_URL`로 간다. 비어 있으면 관리자 화면을 하루 한 번 봐야 한다 |
| 최소 결제 금액 | 엽전을 쓰고 남은 금액이 100원 미만이면 100원을 결제하게 되어 있다. KCP·간편결제 최소 금액이 이보다 크면 결제창이 거절할 수 있다 (실결제로 확인) |
| 간편결제 3종 | 카카오페이·네이버페이·토스페이가 우리 KCP 계약에서 열려 있는지 실결제로 확인 |
| 판매 잠금 중인 상품 화면 | 신년운·연애운·관상 등의 결제 단추는 화면에 그대로 있고, 누르면 서버가 "곧 열려요. 지금은 준비 중이에요."로 막는다. 화면에서 단추를 숨기려면 상품별로 고쳐야 한다 |
| 가입 선물을 이미 쓴 회원 | 수능 기본 풀이(로그인 무료)는 가입 선물 엽전 990냥으로 연다. 선물을 이미 쓴 회원·두 번째 사람부터는 990원 결제가 뜬다 (2026-10-26 결정 그대로) |
| 엽전으로 남은 결제를 환불 | 결제 뒤 구매 실패로 엽전이 된 돈을 환불했는데 그 엽전을 이미 썼으면 엽전 잔액이 마이너스가 될 수 있다 (드문 경우) |
| 내년 수능 | 열람 이름이 `exam_suneung_*`로 해마다 같다. 내년에 다시 팔려면 이름에 연도를 넣어야 한다 |

## 5. 새 상품을 열 때 확인할 것

| 확인 | 어디 |
|---|---|
| 가격을 고객사 설정 prices에 넣었다 (부가세 떨어지는 값, 심사 중인 main은 건드리지 않음) | `tenants/<id>.ts`, 가격 시험 `tests/love.test.ts` |
| 상품 종류(mode)를 PURCHASE_MODES에 넣고, 가격이 없는 고객사에서는 팔지 않게 했다 | `readings.ts` `isPurchaseMode` |
| 이미 산 사람에게 다시 팔지 않는다 | `planForPerson` |
| 산 뒤 열람 표시(topic_unlocks via=상품)를 남긴다 | `purchaseWithClient` |
| 결제 뒤 돌아갈 화면을 정했다 | `payOrders.destination` |
| 판매 잠금(saleOnly)에 넣었다 | `tenants/<id>.ts` |
| 환불 때 다시 잠글 수 있다 (via 로 지울 수 있는 상품이면 `REVOCABLE`에 추가, 아니면 관리자 알림만) | `refund.ts` |
| 풀이를 쓰는 동안 기다림 화면, 실패하면 "결제는 그대로 남아 있어요" + 다시 시도 | 상품 화면 |
| 수험생·미성년 대상이면 보호자 결제 안내 | `PayDialog` |
| 실결제 1건 → 열람 → 환불 신청 → 환불 처리 → 다시 잠김 확인 | 실제 사이트 |
